# Scientific question

Turn the researcher's idea into a question whose answer would change scientific understanding. This is Phase A research design; no experimental findings are implied.

## Working context

Locate the paper-specific workspace from the request and existing artifacts. If the destination is ambiguous, ask before writing. Read existing `question.md` and relevant notes before revising them. Write paper artifacts there; do not modify the framework, skills, or unrelated projects as a side effect. Preserve existing decisions and distinguish researcher statements from proposed assumptions.

## Procedure

1. Identify the phenomenon, system or population, relationship to investigate, and intended scientific contribution. Distinguish a scientific question from a deliverable such as building software or producing a plot.
2. Establish the scope: conditions, scales, available observations or experiments, and explicit exclusions. Separate the question from any favored hypothesis or method.
3. Ask focused questions about missing decisions that materially change the investigation. Offer candidate formulations when useful; mark unconfirmed choices as provisional rather than answering for the researcher.
4. Explain why the answer matters and what is believed to be known. Use sources supplied by the researcher or verified literature for factual context; label unsupported novelty or feasibility claims as unverified. A preliminary search can expose obvious duplication, but does not establish novelty.
5. Consolidate the formulation and record open issues. For adversarial testing use `idea-grilling`; for unfamiliar concepts use `terminology-extraction`, if available. These are optional handoffs, not prerequisites for a useful draft.

## Artifact and completion

Write `question.md` with the central question, motivation, current knowledge and sources, candidate hypotheses or alternative answers, scope and exclusions, available evidence routes, and unresolved decisions. Record review status and interaction preferences only in `workspace.yaml`; keep agent guidance and workflow notes out of `question.md`.

The question is ready for decomposition when the researcher can explain what will be learned, why it matters, and why the answer is not already sufficiently established. If that last point awaits literature validation, retain it as an explicit uncertainty. Report the artifact path and the next unresolved decision; do not automatically start experiments or manuscript writing.
